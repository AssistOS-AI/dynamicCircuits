CLI workspaces

The presence of --workdir selects task analysis; its absence selects KB learning. Workspace preparation creates the required directories, manifests, instructions, and skill links before launching a coding agent.

Purpose and relationship to the runtime

This page explains how a filesystem location becomes a coding-agent workspace. The CLI owns directory creation, input inventory, generated guidance, skill discovery, and external process invocation. The coding agent owns document interpretation and SOP authoring. The compiler and runtime described in the SOP runtime guide execute the resulting circuit files.

There are two modes because reusable knowledge and one task have different lifetimes. Learning produces reviewable KB candidates for future tasks. Analysis produces task-local circuits and reports for the current input set.

Learn reusable circuits

Start with a KB containing documents under input/. The following commands prepare the directory, run Codex, or inspect the invocation without starting Codex:

agent prepare -kbdir ./kb
agent -kbdir ./kb -agent codex
agent -kbdir ./kb -agent codex --dry-run
  1. The CLI scans ./kb/input and writes a hash manifest.
  2. It links the runtime skills and generates learning instructions.
  3. The agent reads the input documents and existing reviewed circuits/.
  4. It writes proposed packages and tests to candidates/ and a coverage report to results/.
  5. A reviewer decides whether a tested candidate is suitable for promotion.

Analyze a current task

Start with task documents under ./work/task-001/input. The KB path identifies reusable reviewed circuits; the workdir identifies the only task directory where generated SOP files and reports belong:

agent prepare -kbdir ./kb -workdir ./work/task-001
agent -kbdir ./kb -workdir ./work/task-001 -agent codex
agent run --kbdir ./kb --workdir ./work/task-001 --agent codex
  1. The CLI creates missing task directories and inventories every regular file under input/.
  2. The coding agent reads the manifest, task documents, and applicable KB circuit interfaces.
  3. It writes task-specific circuits to sop/, compiles them, and executes the circuits used by the analysis.
  4. It writes reports and its coverage summary to results/.

Both single-dash and conventional double-dash forms are accepted. KB and work roots may not overlap because overlap would make read/write authority and input discovery ambiguous. Existing user guidance is preserved, and conflicting skill-link paths produce a structured error.

Knowledge-base directories

      K[KB] --> I[input]
      K --> C[circuits]
      K --> N[candidates]
      K --> R[results]

The KB diagram shows the learning data lifecycle. input/ contains evidence to extract; circuits/ contains reviewed reusable packages; candidates/ contains generated proposals awaiting review; and results/ contains learning coverage and validation reports.

Task-workspace directories

flowchart LR
      W[Task workspace] --> I[input]
      W --> S[sop]
      W --> R[results]
      W --> M[manifests and skill links]

The task diagram shows the analysis boundary. Source files remain under input/, generated circuit source remains under sop/, and reports remain under results/. The manifest and skill links under the same workspace tell the coding agent what to process and how to author supported SOP Lang.

Agent authority

Analysis treats the KB as read-only. Learning uses the KB as the coding agent's current directory, while generated instructions restrict reusable output to candidates/. This restriction is currently instructional rather than a host-mediated filesystem capability; DS008 records the limitation. The former explicit learn flag is rejected because mode is now inferred unambiguously.

--prepare-only stops before adapter construction. --dry-run prints the command, arguments, working directory, and prompt without launching a process. The generic adapter accepts a program through --agent-command and sends the prompt through standard input. Installed compatibility aliases are dc-agent and dynamic-circuits.

Workspace skill catalog

analyze-task enforces complete input coverage and grounded results. author-sop-circuit supplies the implemented syntax and verification loop. circuit-learner separates reusable candidates from task-specific facts. The CLI links the catalog as one directory so the same instructions govern normal tasks and evaluation cases.

Example: an analysis agent uses analyze-task to enumerate every input, switches to author-sop-circuit when it needs a deadline calculation, then returns to analyze-task to connect the circuit output and receipt to the final report. A KB learning run uses circuit-learner instead and writes the same reusable calculation as a candidate with provenance and tests.
