Evaluation catalog

The catalog links all ten evaluation domains. Each domain page keeps one KB separate from three independent task runs and lets you inspect source text, generated SOP, and executor output without mixing their roles.

Purpose of the catalog

The catalog separates evaluation cases so the interface remains usable as the repository grows. An evaluation page explains one domain and three distinct task runs. It does not mix filenames or explanations from unrelated cases. The source material under kb/input/ and each taskN/input/ is human-readable Markdown intended for a coding agent. Reusable reviewed circuits live under kb/circuits/; current adaptation and wiring live under the corresponding taskN/sop/. Official task results are executor-rendered Markdown reports; JSON is neither source input nor a substitute for circuit execution. The KB/task convention explains how to classify files whose role is not immediately obvious.
