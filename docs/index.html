Dynamic Circuits

Dynamic Circuits analyzes a folder of documents by combining a coding agent with executable SOP circuits. The coding agent reads and structures the documents; the local compiler and runtime validate and execute the circuits; reports and receipts are written to a separate results directory.

Problem

A document-analysis task has source files, reusable rules, task-specific logic, intermediate calculations, and final conclusions. These elements need separate storage and explicit provenance so another run can determine which files were read, which rules were reused, which circuit produced each value, and whether execution succeeded.

Dynamic Circuits provides five concrete mechanisms:

RequirementMechanism
Identify all source filesThe CLI scans input/ and records relative paths, sizes, and SHA-256 hashes in an input manifest.
Reuse established analysis rulesReviewed SOP packages are stored in the knowledge base under circuits/.
Keep one task isolatedTask-specific circuits go to sop/; reports and machine-readable outputs go to results/.
Execute calculations reproduciblyThe SOP compiler resolves dependencies and the runtime executes the required graph nodes.
Inspect what happenedRuntime receipts record package identities, node states, input/output hashes, checks, child executions, and the final outcome.

Together, these mechanisms create a traceable path from a source file to a report. For example, a policy document is registered in the input manifest, a reviewed circuit represents its notice-period rule, a task circuit supplies the dates for one case, and the receipt identifies the rule package and values used to classify that case.

Five terms

TermMeaning
Knowledge base (KB)A persistent directory containing source material for learning, reviewed circuits, proposed candidates, and learning reports.
Task workspaceA directory for one analysis, containing its input documents, task-specific SOP files, and results.
SOP circuitA text file that declares inputs, commands, immutable intermediate wires, outputs, goals, and invariants.
Coding agentAn external CLI program—Codex by default—that reads documents and authors or reuses SOP files.
ReceiptA structured runtime record showing which circuit nodes executed and how the outcome was produced.

The KB and task workspace are filesystem scopes. SOP circuits are the executable units stored in those scopes. The coding agent creates or selects those units, while the runtime executes them and creates receipts. The separation lets an agent change its interpretation or task-specific source without silently changing a reviewed KB rule.

Learn into the KB

Use this workflow when the source documents describe rules or procedures that should be available to later tasks.

  1. Create a KB directory and place the source documents in ./kb/input/.
  2. Run agent -kbdir ./kb. The missing --workdir selects learning mode.
  3. The CLI creates the KB folders, input manifest, coding-agent instructions, and links to circuitSkills.
  4. The coding agent reads every manifest entry and the existing reviewed packages in circuits/.
  5. New SOP packages, contracts, provenance, and tests are written to candidates/.
  6. Compilation and tests check mechanical behavior. A separate review decides whether a candidate is promoted to circuits/.
flowchart LR
      I[KB input] --> A[Coding agent]
      A --> C[Candidate package]
      C --> V[Compile and test]
      V --> R[Review]

The diagram follows one candidate from source documents to review. “KB input” is the evidence being learned. The coding agent extracts a reusable rule and packages it under candidates/. Compilation and tests validate syntax, dependencies, positive cases, negative cases, and refusal cases. Review is the trust boundary: only reviewed material can later move into circuits/.

Analyze one task

Use this workflow when a specific set of documents must produce a report.

  1. Create a task directory and place all source files in ./work/task-001/input/.
  2. Run agent -kbdir ./kb -workdir ./work/task-001. The presence of --workdir selects analysis mode.
  3. The CLI inventories the task inputs and prepares sop/, results/, instructions, and skill links.
  4. The coding agent accounts for every input file, inspects applicable reviewed KB circuits, and writes task-specific circuits under sop/.
  5. The agent compiles and runs the circuits. The runtime returns outputs and receipts or a classified refusal, rejection, or error.
  6. The agent writes the analysis and coverage summary under results/. The KB remains read-only during this workflow.
flowchart LR
      I[Task input] --> A[Coding agent]
      K[KB circuits] --> A
      A --> S[Task SOP files]
      S --> X[Compiler and runtime]

The first analysis diagram shows circuit construction. Task documents supply case-specific facts; KB circuits supply reviewed reusable rules. The coding agent connects both sources by writing task-local SOP files, and the compiler turns those files into a validated dependency graph.

flowchart LR
      X[Runtime outcome] --> R[Receipts]
      X --> O[Public outputs]
      R --> P[Results report]
      O --> P

The second diagram shows publication. Public outputs contain the values requested by the circuit interface. Receipts contain the execution evidence behind those values. The coding agent uses both to write the report, so the report can distinguish a computed conclusion from a refusal, failed check, runtime error, or unresolved source conflict.

Current status

The current implementation provides workspace preparation, Codex and generic agent adapters, the SOP parser, package discovery, static graph compilation, nested circuit execution, canonical values, local goals and invariants, and structured receipts.

The maintained specifications also define later components: semantic fact indexes, automatic template matching, mandatory fixed-point closure, assurance profiles, trust registries, persistent caches, artifact stores, acceptance certificates, hardened isolation, and distributed execution. Those components are marked as planned in the relevant DS files.

Where to continue
