Analysis lifecycle

The lifecycle ingests source artifacts, extracts provenance-linked facts, selects and executes circuits, evaluates assurance requirements, records repair attempts, and publishes the resulting report and receipt.

Purpose and relationship to the system

This page orders the concepts from the other documentation into one end-to-end process. The CLI prepares the source and workspace boundary. The concept model defines artifacts, facts, templates, and attempts. The runtime compiles and executes explicit circuits. The assurance layer evaluates completeness and acceptance, while the operations layer persists receipts and manages reuse.

The complete lifecycle is a target architecture. The current release implements workspace preparation, explicit circuit authoring, compilation, execution, local checks and goals, and runtime receipts. The sections below identify the later registry, closure, acceptance, attempt, and publication responsibilities in their execution order.

Phases A–I

Prepare the graph

flowchart LR
  A[Ingest sources] --> B[Interpret facts]
  B --> C[Discover circuits]
  C --> D[Wire instances]

Graph preparation starts by storing immutable source artifacts with digests and locators. Interpretation publishes facts and claims tied to those locators. Registry discovery finds candidate templates, deterministic matchers verify applicability, and wiring creates explicit circuit instances with bound inputs. The output of this stage is a compiled dependency graph.

Execute and evaluate

flowchart LR
  D[Compiled graph] --> E[Execute]
  E --> F[Mandatory closure]
  F --> G[Assurance gates]

Execution evaluates only nodes required by outputs and obligations. Mandatory closure indexes new facts, runs every applicable mandatory matcher, executes new instances, and repeats to a fixed point. Assurance then checks goals, invariants, trust, conflicts, capabilities, budgets, and receipt completeness.

Publish or repair

flowchart LR
  G[Assurance result] -->|accepted| P[Publish]
  G -->|failed| A[New attempt]
  A --> E[Execute revised graph]

An accepted assurance result publishes the requested report, artifacts, and final receipt. A refusal, rejection, inconclusive result, or technical error creates diagnostic evidence. Repair preserves the failed attempt, records the changed packages and reason, and executes a child attempt. This lineage lets reviewers compare exactly what changed.

DS027 includes legal exception, scientific counterexample, and cross-document conflict reference flows. Their inputs, circuits, and results are available in the evaluation file browser.

Example across the lifecycle

For the notice-period eval, ingest stores the rule, structured policy, and three cases. Interpretation exposes policy and case values. The root circuit wires them to the policy circuit. Execution produces three findings and aggregate statistics. The current local goal confirms that every case has a finding. A future strict profile would additionally prove matcher coverage, package trust, conflict handling, and final receipt completeness before publishing an acceptance certificate.

Roadmap and design choices

The staged roadmap starts with syntax and deterministic IR, then adds runtime execution, workspace orchestration, persistent evidence, semantic templates, mandatory closure, hardened capabilities, and distributed processing. Each milestone has its own implementation and conformance requirements. Module and schema compatibility rules are in DS024.

The architecture uses compiler/dataflow SSA for circuit execution, rule-system fixed points for mandatory closure, workflow-style effects and attempts for operations, and proof/evidence-style receipts for audit. DS025 compares these choices with Datalog, CHR, attribute grammars, semantic parsing, rewriting systems, proof assistants, e-graphs, dataflow engines, and workflow systems.

What exists now

The current repository delivers parser, package discovery, graph compiler, deterministic runtime, local checks/invariants, receipts, inferred CLI modes, skill-linked agent workspaces, three serious evals, and documentation/integrity tests. Attempts, semantic indexing, automatic wiring, closure, profiles, trust registry, persistent cache, artifact store, production isolation, certificates, and distributed execution remain planned.
